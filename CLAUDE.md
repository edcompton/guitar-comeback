# Guitar Comeback HQ

A single-page static app tracking Ed's guitar comeback: song boards with progress chips, the weekly practice rhythm, and a 12-week arc. Served by GitHub Pages; edited here via Claude Code. No build step, no dependencies — keep it that way.

## File map

- **`data.json`** — the file that changes. Song boards (with chips), the "This week" block, and `meta`. Almost every routine update is an edit to this file only.
- **`index.html`** — page shell, all styling, and the render logic that draws `thisWeek` and `boards` from data.json. Static prose sections (player profile, weekly rhythm, session shape, phases, resources, rules) live directly in the HTML — edit them there when they genuinely change, which is rarely.
- **`sw.js`** — service worker. Network-first for index.html and data.json, cache-first for the rest. **Bump `CACHE_VERSION` whenever you change icons/manifest or want to force clients to refresh cached assets.** data.json changes do NOT need a version bump (network-first picks them up).
- **`manifest.webmanifest`, `icons/`** — PWA shell so the page installs from Chrome on Android.
- **`backlog.json`** — *generated*, not hand-edited. The "From your Spotify" board, built by `tools/`. Rendered after the curated boards; the page works fine without it. Regenerate rather than editing by hand.
- **`tools/`** — the Spotify → backlog pipeline (`1_pull` → `2_tag` → `3_build`). See `tools/README.md`. Uses its own Anthropic API key from `.env` and a cheap model, deliberately outside the Claude Code loop so a 2,000-song run costs cents rather than session tokens.
  - Spotify gives new apps **no artist genres** (empty field) and **403s the bulk `/v1/artists`** endpoint — verified, not guessed. So tagging runs on artist + title alone, which is enough for well-known music. Don't reinstate a genre crawl without checking the field is actually populated first; a 1,600-artist sweep earned a 24-hour throttle.
  - The backlog board is deliberately **short (12)**. Song supply was never the bottleneck — 1,023 of Ed's liked songs qualify. It's a queue, not a library; keep it that way unless he asks otherwise.

## Editing conventions

- **Moving a song's status** = edit its `chip` in data.json. Chip classes: `now` (current focus, rust-red), `next` (amber), `later` (dim), `done` (sage green). Keep chip text short: "week 6", "up next", "nailed ✓", "phase III".
- **Done songs stay on the board** with chip `{"t": "nailed ✓", "c": "done"}` — the visible trail is motivational; never delete progress.
- At most one or two songs per board should be `now`.
- **Adding a song**: kebab-case `id`, `parts` array (each `{t, u}` — `u` is the Ultimate Guitar tab URL; omit `u` for non-linked items), `small` for artist/notes, `chip`. Songs with two versions get two entries in `parts`.
- **Weekly update**: rewrite `thisWeek` (title, lede, rows — `rows[].anchor: true` shows the ⚓) for the coming week, and bump `meta.updated` (YYYY-MM-DD). Update `meta.phase` when the phase changes.
- **Never invent progress.** Only move chips when Ed says so — he'll paste updates like "Guitar update: nailed — These Days (Nico)" (generated by the page's ✓ buttons) or just describe it. When in doubt, ask.
- Don't remove the habit rules or soften the minimum-viable-session language. Consistency-over-intensity is the design principle of the entire plan.
- **The backlog board is generated.** To change what it suggests, edit the `RUBRIC` in `tools/2_tag.py` (or the `3_build.py` flags) and re-run — don't hand-edit `backlog.json`, the next run overwrites it. Promoting a backlog song to real practice means *moving it into a curated board in `data.json`*; `3_build.py` then stops suggesting it automatically.
- **Never commit `library.json`, `tags.json`, or `.env`.** The repo is public; the full liked-songs dump stays local. They're gitignored — keep it that way.

## Ed context (for a fresh session)

- Guitars each have a job: **Martin** (standard tuning, fingerstyle/folk-blues revival) · **Epiphone Dove** (lives in open D, dedicated slide) · **Strat + Bassbreaker** (electric blues lab, stays plugged in).
- Week rhythm: **Tue = Electric Blues Lab** and **Thu = New Song Workshop** are anchors; other evenings mood-led from the menu; Sunday ~18:00 is the 10-minute weekly review. Daily slot ~19:30 (Todoist reminds him).
- Arc: Phase I Reconnect (revive old repertoire) → II Build (new songs, blues lead, slide licks) → III Stretch (Kensington Blues rebuild, improv fluency, "Living Room EP" recordings).
- Background: strong fingerstyle player (Jack Rose's Kensington Blues was his peak), returning after a long break; growth edges are pick technique, electric vocabulary, slide, and above all consistency.
- His Todoist has the recurring practice tasks; his Spotify has the "Guitar Comeback" playlist. This repo is the canonical plan; a chat-based copy in Claude Cowork may exist but is no longer the source of truth.

## Deploy

Live at **https://edcompton.github.io/guitar-comeback/** (repo: `edcompton/guitar-comeback`, this Mac mini at `~/guitar-comeback`).

Deploy = commit + push to `main`; GitHub Pages serves the repo root. After any change: `git add -A && git commit && git push`. Pages rebuilds in a minute or so. Verify with the Pages URL, not file://.

## Testing locally

`python3 -m http.server 8000` then http://localhost:8000 — needed because `fetch('data.json')` and the service worker don't run from file://.
